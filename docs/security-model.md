# 安全、权限与隐私模型

## 账号与会话

- Access Token 为 15 分钟 HS256 JWT，校验 issuer、audience、session ID 与当前 access JTI。
- Refresh Token 仅保存加 Pepper 的 SHA-256；轮换使用条件更新，同一 Token 并发刷新只有一个请求成功。
- 退出、重置密码和注销申请会撤销服务端会话，旧 Access Token 随即无法通过会话校验。
- 密码使用 bcrypt cost 12；兼容旧 bcrypt 哈希后在成功登录时升级。
- 短信验证码限时、限频、最多五次错误尝试并使用原子消费；生产不返回验证码。

## 远程关爱

- 关系状态固定为 `pending/active/rejected/revoked/expired`。
- 只有被关爱人可以配置共享指标和到期时间。
- 每次跨账号健康查询同时校验关系、指标和双方到期状态，并记录允许/拒绝审计。
- 撤销后下一次查询立即失败，不依赖缓存延迟。

## 健康数据

- 管理后台默认仅显示汇总和计数；原始记录只允许超级管理员与健康数据审计员查看。
- 每次原始健康数据访问记录管理员、用户、请求 ID、时间和记录数。
- ECG 波形 gzip 后存私有对象存储；数据库保存摘要、采样参数、大小与归属索引。
- 阈值事件只表示用户设置的提醒，不产生诊断结论。
- AI 分析前记录单独同意版本和撤回状态；仅向供应商发送去标识化汇总与证据索引，不发送姓名、手机号、设备地址或原始 ECG。
- 无效、可疑占位和未知数据不进入报告结论；详细报告始终标识为 AI 生成的健康管理参考，异常提醒不受付费限制。

## 商城、支付与员工

- 新商城对象使用主账号 UUID；旧系统 ID 仅存兼容映射，手机号和 UnionID 不能在冲突时自动合并账号。
- 聚水潭是 SKU、库存和履约权威来源；后台禁止直接修改 ERP 编号、内部商品名、SKU 和库存。
- 支付金额、币种、商品和权益由服务端确定；微信、支付宝、StoreKit 回调必须验签、匹配业务对象并按供应商事件 ID 去重。
- 员工企业微信会话与会员/管理员会话隔离；推广赠券原始令牌只返回一次，数据库只保存 SHA-256，领取使用事务防止并发重复。
- 退款成功后才更新订单与权益；数字报告退款撤销对应阅读权限，会员退款撤销剩余次数及关联报告。

## 推送与日志

- Push 载荷只包含 `eventId`、`type`、`deepLink`，禁止手机号、Token 和健康值。
- Worker 使用数据库 Outbox、Redis 锁、指数退避和死信状态；无安装实例视为无需外部投递，不伪造客户端展示。
- 生产异常响应不含堆栈、服务器路径或供应商原始错误；内部错误只进入受控日志。

## 管理后台 RBAC

| 角色 | 主要权限 |
|---|---|
| 超级管理员 | 全部管理与账号/集成配置 |
| App 运营 | 会员摘要、关爱、预警、通知、客服和更新配置 |
| 商城运营 | 商品展示、分类、订单、物流、售后、评价、优惠券和推广 |
| 财务 | 支付、退款、健康报告价格和对账 |
| 内容编辑 | 内容分类、文章和协议 |
| 客服 | 会员摘要与反馈处理 |
| 健康数据审计员 | 原始健康数据审计查看 |
| 集成管理员 | 第三方公开配置和加密密钥写入/清除 |
| 接口文档编辑 | 业务说明草稿和提交审核；发布仍需超级管理员 |
| 只读人员 | 非敏感只读页面 |

所有管理端写操作由拦截器写入审计日志。第三方密钥通过写入型表单提交，使用主机外置 `INTEGRATION_MASTER_KEY` 加密；后台只显示 `hasSecret`，任何列表、详情、日志或导出都不得回显明文。配置写入后先显示“尚未通过真实调用”，只有供应商/存储成功响应才更新验证时间。部署重启的 seed 不覆盖后台保存的状态和公开配置。轮换主密钥必须先解密并重加密现有记录。

## 上线前必须完成

1. 轮换旧文档中可能出现过的凭据。
2. 使用最小权限账号配置旧库、商城迁移源、对象存储、短信、AI、Push、微信/支付宝/Apple、企业微信、聚水潭和备份仓库。
3. 执行越权、支付伪造回调、赠券并发领取、文件类型/大小、Token 重放、短信限流、日志脱敏与依赖扫描。
4. 确认生产 `ALLOW_TEST_OTP=false`、`ENABLE_PUBLIC_DOCS=false`，且只开放 22/80/443。
