# 架构与数据边界

## 目标结构

```text
Flutter App / 商城 H5 / 原小程序
        │
        ├─ V2 /api/saydian-app/v2
        ├─ 商城兼容 /api/saidian-mall/v1
        └─ V1 兼容路由
                 │
        NestJS 模块化单体 API
        ├─ 账号 / 会员 / 协议
        ├─ 健康 / 设备 / 关爱
        ├─ 健康档案 / 报告 / 权益
        ├─ 商城 / 订单 / 售后 / 推广
        ├─ 统一支付 / 通知 / 内容 / AI
        └─ 总后台 / 接口中心 / 审计
                 │
        PostgreSQL（core / health / commerce / ops 模块边界）
                 │ 事务 Outbox
        独立 Worker ──> Redis 去重锁 ──> 报告 / 推送 / ERP 适配器
                 │
        私有 S3 兼容对象存储（头像、反馈附件、ECG 压缩文件）

        聚水潭：SKU / 库存 / 履约权威来源
        微信 / 支付宝 / Apple：支付供应商
```

## 设计决定

1. 使用模块化单体和独立 Worker。当前吞吐与团队规模不需要微服务，事务边界也更清楚。
2. App 与商城使用同一 PostgreSQL 和会员 UUID，通过模块、表、服务、权限及审计形成 `core`、`health`、`commerce`、`ops` 逻辑边界；健康原始数据不进入商城业务对象。
3. 原商城会员、商品、订单等旧 ID 只进入兼容映射；运行期不再通过网络调用第二套商城身份服务，也不使用手机号作长期主键。
4. V1 拼写错误和 multipart 只存在于 `legacy` 模块；V2、数据库和共享类型全部使用规范字段。
5. 手机与手表间的 BLE 指令不进入服务端。服务端只保存绑定、能力快照、固件、在线时间和同步游标。
6. 未知健康值保持缺失；迁移器和 API 均不把未知值补为 `0`。
7. 旧订单只保存不可变投影并合并展示，不进入支付、库存或 ERP 流程；新订单只在主系统创建一次。
8. 聚水潭是 SKU、库存和履约的权威来源；总后台只维护展示、营销和上下架，所有写能力必须逐项以真实授权验收。
9. 统一 `PaymentIntent` 只使用服务端金额；微信、支付宝、StoreKit 回调验签、去重、退款和权益撤销集中处理。
10. 健康报告先由确定性规则生成证据索引，再由 AI 生成通俗说明；未知或无效数据不参与，异常提醒不进入付费墙。

## 模块职责

| 模块 | 主要职责 | 明确不负责 |
|---|---|---|
| `auth` | 注册、登录、短信、刷新轮换、退出、重置、注销申请 | 微信/短信供应商内部实现 |
| `health` | 批量幂等同步、历史、阈值规则、预警事件、ECG 索引 | 诊断、治疗结论 |
| `devices` | 绑定、解绑、能力/固件/游标快照 | BLE 指令与测量算法 |
| `care` | 邀请、授权、撤销、到期、访问审计 | 无授权健康查询 |
| `notifications` | 站内消息、安装实例、活动、未读与多端已读 | 推送载荷中的敏感值 |
| `content` | 百科、协议、AI 会话与供应商适配 | AI 伪回答 |
| `support` | 反馈、客服/更新配置、文件与 ECG 对象 | 公开暴露私有附件 |
| `commerce` | 商品展示、购物车、地址、订单、物流、售后、评价、优惠券、员工推广及旧订单投影 | 直接覆盖聚水潭权威库存 |
| `billing` | 商城/报告/会员统一支付单、验签、退款、对账事件和权益 | 客户端决定金额、伪造支付成功 |
| `reports` | 健康档案、资格、同意、证据、报告、权益、按需 PDF | 诊断、处方、付费屏蔽异常提醒 |
| `api-docs` | 代码路由、可编辑说明、审核发布、回滚、脱敏导出 | 后台任意修改方法和路径 |
| `admin` | RBAC、商城/健康/支付/通知/内容/集成与审计 | 未授权原始健康查看、密钥回显 |

## 可扩展点

- 短信使用 `SmsAdapterService`；生产可接受控 Webhook，未配置时返回普通用户提示。
- AI 采用 OpenAI-compatible `/chat/completions` 适配，供应商未配置时不创建伪回复。
- Push Provider 已有 Disabled/Mock/JPush 边界；APNs 证书缺失时保持禁用。
- 支付、企业微信、聚水潭、短信、AI 和推送运行时优先读取加密集成密钥；主机外置主密钥缺失或真实检测未通过时保持未配置。
- 原商城的只读迁移器保留来源提交和永久 ID 映射；正式切换后原商城服务仅作 14 天回滚来源，不允许双写。
