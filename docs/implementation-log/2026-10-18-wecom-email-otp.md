# 企业微信邮箱验证码直连

## 请求、基线与范围

用户要求在中国站第三方服务中启用企业微信邮箱。原邮箱配置只有 HTTPS webhook，邮箱地址不能当作接口 URL 填入；企业微信员工推广凭证不自动复用。

`tools/Start-Change.ps1` 在干净 main 上 fetch/ff 成功，本地与 origin/main 基线均为 `20a8dec4517791022e4f4532cfc65bc820591dbf`。独立分支 `codex/wecom-email-otp-20261018`。无数据库迁移，不改其他产品配置。

## 实现

- email_otp 增加 wecom_smtp：完整发件邮箱、加密客户端专用密码；固定腾讯企业邮 smtp.exmail.qq.com:465，TLS≥1.2、证书验证开启、限时、禁止 SMTP 调试日志及文件/URL 读取。基于锁定的 Nodemailer 10.1.2 及其 QQex 服务定义，不实现自制 SMTP 协议。
- 只发往一个已校验邮箱，显式 envelope，固定主题/内容模板；登录验证码不记录或回显，供应商异常不向客户端透出凭证、邮箱或原始应答。
- 保留 CONFIGURED 和 deliveryVerified 双门禁；新配置、改发件人、切换渠道或更换/清除凭证均重置投递验收。暂停、缺少凭证或未验收时邮箱登录保持不可用。
- 集成管理员/超级管理员可发送独立测试邮件（POST integrations/email_otp/test，每 IP 每分钟 3 次，原后台审计）；不建会员/验证码或自动确认收件。维护/外发暂停时禁止测试；演示环境由既有凭证读取门禁阻止。SMTP 受理不能等同于收件箱实际收到。
- 后台在同页维护配置和测试收件地址，先保存、重开再测试；只读用户、未保存表单、发送中的重复点击/保存、异常结果不得发送或误报成功。
- 不读取企业微信管理员密码，不代用户生成或填写客户端授权码。已请求确认发件邮箱、测试收件邮箱，并由用户将浏览器切到企业微信邮件页；原腾讯云终端因网址策略被禁，未绕过。
