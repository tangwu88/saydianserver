# 2026-11-21 健康记录按原时间入库

## 背景

华为连接 R21 后确认有部分健康记录缺少云端回执。此前后端把晚于当前时间 10 分钟的记录标为 `future_time`，并缓存整批回执。用户要求取消上报时对当前时间的比较，按设备原始时间保存记录。本轮以远端 main `5138108` 为基线，两个中国站 readiness 已核对到同一版本。

## 修改

- 健康记录测量时间、来源信息中的测量时间及睡眠时段结束时间均按上传值处理，后端取消是否超前的判断。UTC 序列化保留同一时刻，独立的时区偏移和测量数据继续保存。日期格式和时段结构仍按原接口约定解析。
- 手机使用相同幂等键和内容重试时，服务端识别旧回执中的超前时间拒绝，按当前规则重新校验并只写入已经可接收的记录。旧版睡眠时段和日汇总的来源时间检查返回 `invalid_source`，也在当前规则明确有效后补传。已确认记录不重复写入。记录和修正后的回执在同一事务提交。
- 既有 Android 可以继续使用原上传入口及账号，服务端处理旧回执无需更新安装包。变更无需数据库迁移。

## 验证

- 定向测试 29 项通过，覆盖未来测量时间、未来睡眠区间、未来日汇总来源时间和重复使用旧回执键。
- 首次本机 Vitest 使用桌面客户端自带 Node，macOS 拒绝加载签名团队不同的 Rollup。改用预先安装到临时目录的 Node 22 后通过。首次全量中应用包测试夹具的临时目录实际路径和符号链接路径不同，改用隔离的物理路径复测。
- `pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm api:docs:check`、`pnpm tools:test` 及 Node/Python 部署脚本检查均通过。API 全量 1,642 项通过、101 项按默认配置跳过，接口目录核对 603 条。没有生产机凭据参与测试。
- 初始化独立 PostgreSQL 16.14 前，为临时运行时恢复发行包声明的动态库链接。空库完成全部迁移后，通过与正式路由共用的 `HealthService` 验证合成步数、心率、温度和睡眠。用同一旧回执键补传四条未来记录并回读，原时刻、时区偏移和数值一致。同一请求重放或改用新键均未增加记录，同一键改请求体返回 409，另一账号查不到这批数据。临时数据库已停止。
- 正式中国站部署及华为 R21 的原始待传记录实机验收另记。
