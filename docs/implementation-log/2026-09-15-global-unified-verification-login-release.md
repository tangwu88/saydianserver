# 2026-09-15 国际版商城统一验证码登录发布

## 目标与范围

- 将国内主分支已经完成的“手机号/邮箱验证码登录、移除注册与密码入口、微信首次授权绑定手机号”变更同步到国际版独立部署分支。
- 只移植提交 `eed59ea3a45bfba7b918ec01a68e0e1315ba0f32` 的登录相关改动，不合并主分支其余支付、数据库或部署改动。
- 保留国际版现有的短信 Webhook 和独立 `sms_global` 配置边界；国内 `sms` 集成与国际短信配置不共用。

## 配置复核

- 国内生产公开能力接口仍返回 `sms.enabled=false`，说明服务端当前未把该配置判定为可用。
- 可用条件包括配置状态为 `CONFIGURED`、接入方和必要字段完整、加密凭证可成功解析；本轮未读取或输出任何 AccessKey。
- 应用内浏览器控制组件当前无法连接已登录页面，因此没有绕过会话读取后台表单或密钥；以上结论来自生产公开能力接口与源码判定条件。

## 实现

- 国际版商城登录页默认手机号，可切换邮箱，统一请求和消费一次性验证码，不再展示注册、密码或忘记密码入口。
- 国际版保留现有可编辑 `+` 国家区号输入和 E.164 标准化，避免引入该分支尚未包含的区号选择组件。
- 微信首次授权继续要求手机号验证码绑定；已有已验证手机号的微信身份后续授权直接建立会话。
- 国际版能力接口增加短信、邮箱及默认登录通道字段，验证码投递仍严格依赖独立集成配置与验收状态。
- 管理后台增加邮箱验证码 Webhook 配置，并确保首次启用时持久化所选 provider。
- 首次发布后的线上能力验收发现，`/admin/` 连接国际 API 并保存的是 `sms` 阿里云配置，而国际验证码投递历史上只读取 `sms_global` Webhook，导致“后台已配置”与“商城显示未配置”并存。
- 后续修正让国际短信优先保留既有 `sms_global` Webhook；未选择该方式时复用后台 `sms` 阿里云直连配置，仅向 `CN`、`+86` 手机号开放，并在发给阿里云前转换为大陆 11 位号码。其他国家仍保持关闭，避免误用大陆签名和模板。
- 国际 API 同步加入阿里云官方 SDK、完整性检查和失败脱敏；配置能力检查不调用供应商，真实发送成功后才更新集成检查时间。

## 验证边界

- 未发送真实短信或邮件，未产生供应商费用。
- 无数据库结构变更或数据迁移。
- 发布完成前，以国际版 `/global/health` 返回的新提交 revision 为上线判据。
