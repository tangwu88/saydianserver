# ERP任务：聚水潭令牌自动续期

用户要求根据自研商家授权文档，在商城ERP任务加入自动续期。已读AGENTS、handoff、最近实施记录及官方docId23/70（上轮已实际浏览器读取，参数与本轮截图一致），本轮再次查询官方入口。签名采用appSecret前缀加字典排序参数，不复用业务旧版网关签名。

## 基线与边界

- 原分支HEAD31e784f，fetch后origin/main为c733d26d6ed07b9ef27745d8534a0934ac24a3a2。原工作区有用户实施记录修改及法律资料/SayRing-harmony未跟踪文件，全部保留；创建codex/jushuitan-token-renewal-20261113从最新origin/main开始，不覆盖、不强推。Start/Publish只接受干净main，本轮保留用户文件并手动执行等价检查及显式文件提交。
- 无数据库迁移，使用既有私有AppSetting保存非敏感计划，令牌与原集成密钥同样AES-256-GCM加密在IntegrationSecret。新功能默认未配置，不自动猜测旧令牌有效期，不调用生产授权、不重试历史订单、不改变原维护或Worker开关。令牌首次录入须同次有效access/refresh令牌和真实获取/到期时间。

## 实现

- ERP任务新增续期卡片，显示启用状态、到期/计划时间、最近成功与异常；超级管理员、集成管理员可配置，商城运营及只读角色只查看。新GET/PUT有后端角色保护，响应、普通配置、审计不返回令牌。界面密码输入不回显，提交结束及卸载清空。
- Worker每分钟检查，遵守维护/停写/聚水潭Worker开关；一般安排到期前3天，获取后至少16天才请求，避免15天内无效刷新。固定正式HTTPS refreshToken端点，拒绝重定向，20秒超时；同次响应必须包含有效的两个令牌与expires_in。
- 配置行/计划行事务锁先持久记录RUNNING再调用供应商，多Worker不会同时刷新。成功时两种令牌、有效期与脱敏系统审计同一事务提交；保留AppKey/AppSecret/店铺等原配置。用加密版本指纹绑定有效期，防止集成中心换授权后沿用旧时间；HTTP期间凭据改变时不覆盖新资料。
- 已过期、供应商拒绝、凭据缺失、断电/超时导致结果不确定时停用自动续期并提示核查/重新授权，不盲目重复刷新。关闭再打开不能绕过重新授权要求。外部令牌轮换与本地事务无法跨系统原子提交，崩溃窗口明确进入人工核查；不以“自动重试”掩盖可能丢失的新令牌。
