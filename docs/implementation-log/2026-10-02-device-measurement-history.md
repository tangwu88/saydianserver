# 2026-10-02 设备测量记录与设备来源信息

## 目标

后台设备详情新增测量记录，与连接记录并列展示。会员原始健康记录展示实际收到的设备标识、型号和测量来源类型。Say Ring 与 Health 客户端分别补齐真实来源元数据后联合验收。

## 实现

- 新增 `GET /api/saydian-app/admin/v1/devices/:id/measurements`，限超级管理员与健康审计员访问；审计员须填写业务原因，所有读取先落审计日志，审计失败不返回记录。
- 查询同时按设备绑定 ID 和会员范围的设备指纹匹配，可包含绑定前已上报、当时尚无 `deviceBindingId` 的数据；记录按时间倒序分页，默认每页50条、最多100条，支持查阅全部历史。
- 每条结果只返回后台稳定脱敏设备标识，不暴露数据库原始设备指纹；型号、来源和平台仅展示客户端实际提交的字段，不补造缺失值。
- 设备详情的连接历史与测量历史并排显示，测量值可直接浏览、完整字段可展开查看，小屏堆叠；无权限、取消授权和请求错误均有状态提示。
- 将接口加入人工说明并重新生成 API 目录，无需数据库迁移。

## 验证

- API 设备测量、原始健康、设备快照和健康可靠性测试：39 项通过。
- 后台全量测试：161 项通过；`vue-tsc --noEmit`、Vite 生产构建通过；API 文档生成检查、客户端路由契约检查、`git diff --check` 通过。
- API 全量测试：882 项通过、4 项跳过；另有维护中间件的3项既有测试因 mock 响应缺少 `status()` 失败，与本次设备功能无关。
- 服务端 `tsc` 检查受工作区复用的旧 Prisma Client 影响：客户端模型与当前 schema 不一致，并在已有设备 MAC、连接事件、健康聚合等多处报错；未改写其他工作树依赖来掩盖该环境问题。

## 联调状态

- Say Ring 与 Health 的专属任务已收到明确联调授权。Health 已核对 SDK：设备标识、平台、origin 和测量来源可沿现有记录上传；当前 SDK 返回的广播名、设备显示名或 hardwareVersion 均不足以证实产品型号，因此 `source.model` 保持省略，不用近似值填充。未知设备标识同样不补造，也不触发真实健康数据上传。
- 当前此工作区只实现服务端和后台。客户端改动、合并提交、生产部署及真实账号验收尚未完成；需等待两个客户端任务结果后再进行端到端验收。
