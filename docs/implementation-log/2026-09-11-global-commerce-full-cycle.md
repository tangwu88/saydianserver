## 新增用例

- 已保留前轮邮箱/手机号登录、未验证/临时会话拒绝、CN/CNY、非 CN 拒绝、缺支付字段无 PaymentIntent、条件报价、订单/支付幂等及越权用例。
- 可领取券列表排除员工赠券池；两会员竞争最后一个公开额度（总额度 2，其中赠券预留 1），只生成一条 claim、计数 1，赢家丢响应后重试可读回，不能占用赠券额度。
- 待付款订单占用 333 积分和优惠券；取消后库存、积分、券均归还，重复取消不能重复加积分；归还的同一券用于后续正式合成购物流程。
- 商品 3 件 × 1000 分，券 101 分，积分 1000 分，运费 599 分，现金应付 2498 分；订单行商品现金 1899 分，款项与积分分摊来自实际统一报价。
- 无效签名和有效签名但错误金额均不能使订单变已付；相同/新事件号重投成功付款回调不重复变更版本。
- 实际 AdminService 分两个包裹发出 1/2 件；部分发货不能确认整单收货，运单重试幂等、同运单变更数量冲突。无权限角色不能发货或申请单退运费。
- 顾客实际收货后评价；收货前和跨会员评价拒绝，重复评价返回同一记录，订单详情回显评价。
- 同商品连续三次各退一件：每次现金 633 分，积分依次 333/333/334，运费均为 0。售后旧版本同幂等键重放返回原单，不增加数量占用；改正文同键 409，处理中不可再申请同商品。
- 第二次使用退货退款：顾客提交物流不等于商家收货，未确认 RETURNED 前退款失败；越权提交物流拒绝，重复相同物流幂等。
- 退款传输仅 PROCESSING 时积分仍冻结；实际成功回调后才返积分、完成售后；重复回调不重复返还。各次结算后订单恢复已完成履约，剩余商品可继续售后。
- 商品全退后仅剩 599 分运费，经后台单独申请/审核后回调结算；不新增积分流水，最终订单/支付均 REFUNDED，可退运费归零。
- 1 分与 999 分两商品、999 积分另建已付订单：1 分商品现金分摊为 0，该项售后只返 1 积分，重复执行一次有效，不产生零元渠道退款；剩余现金商品仍可履约。

## 清理保护

- Serializable 同事务检查所有本轮会员/商品/SKU/管理员/券的精确 ID、marker、创建时间；拒绝任何其他会员订单、购物车、收藏、评价或券领取引用。员工赠券 grant/gift 有级联关系，因此明确要求本轮券无员工授予/赠券，本轮用户无赠券领取关系，不能依赖外键报错保护。
- 已付款清理仅放行工具明确记录的 `paidOrderIds`，且支付商户必须为内存合成商户、渠道交易号为本轮 marker+订单 ID、回调 payload 含本轮 runId；未付款旧预览规则不放宽。
- 校验商品级售后归属、退款关联/合成渠道编号、包裹本轮运单前缀、评价归属、积分账本关联、后台发货审计实体及精确回调 eventKey/创建时间/payload。不删除任何 ERP job 或 Outbox 来掩盖副作用；相关计数必须为 0，否则保留夹具人工检查。
- 清理按依赖顺序删除本轮回调/审计、积分账本、退款、售后、评价、券领取、支付、订单、购物车/地址、会员/商品/券/管理员，再校验精确 ID 计数为 0。原 demo 和旧预览夹具仍保留，不能宣称整个库为空。
