## 最终行为

- 微信内仅提供公众号 JSAPI；手机浏览器提供微信 H5 / 支付宝 WAP；桌面提供微信扫码 / 支付宝网页支付。全部沿用现有商户配置、验签、查单、回调及充值入账事务，不按客户端结果直接增加余额。
- 支付宝按商城相同传输保存签名字段：UTF-8 表单，网关公共字段放查询参数，原始 biz_content 放 POST 正文，同窗跳转。微信 H5 返回原充值详情，JSAPI 等待桥接就绪。未配置渠道和未绑定会员明确显示原因。原充值表渠道 CHECK 同步扩展 JSAPI / H5，保留旧合法渠道；真实 PostgreSQL 模拟入账验证两种新渠道均不被原约束拒绝且并发仅入账一次。未确认充值保留原请求与支付关系，切换环境不创建替代扣款。
- JSAPI 的 openid 只从总管理员明确绑定且已验证的商城会员读取，匹配当前公众号 appId；不接收客户端提供的付款身份。已有人工创建的伙伴需要在“伙伴账户 → 绑定商城会员”明确绑定后使用微信授权进入。
- ERP remark 保留受信任伙伴名称和已有管理员备注，去除自动伙伴 UUID / 账号编号；shop_sku_id 为订单行保存的系统 skuId，ERP sku_id 仍用 ERP 规格快照，原客户留言保持。
- 采购商品查询和总数在服务端过滤：仅已上架、启用且当前等级具有有效合作价的规格；没有这些规格的商品不会出现在分页列表。报价和提交仍重新验价，原库存 / 幂等 / 余额规则保持。
- 商城个人中心新增申请 / 合作平台入口，申请归属当前已验证会员。同一会员只保留一个待审核或通过申请，重复请求核对内容；总管理员选择合作等级审核，原子创建独立零余额 / 零保证金账户并审计。未通过显示原因，可重新申请。新账户通过商城进入，密码登录可由管理员重置密码开通。
- 微信内未登录的伙伴入口跳转原 H5 会员登录与公众号授权、验证及原隐私同意流程；不替用户勾选协议。已绑定会员通过哈希存储的 120 秒一次性票据进入伙伴平台。S256 PKCE 将票据绑定发起浏览器，拒绝转发 / 重放；凭据使用 URL fragment，兑换前清除，原会员令牌不传给伙伴前端。
- 兑换同时核对来源会员会话、联系方式验证、伙伴启用和账户版本；重置密码、停用、解除绑定、会员退出 / 失效阻止旧访问。来源会话删除时删除对应伙伴会话，避免影响原会员注销清理。会员推广归属 partnerId 与账户管理者 linkedMemberId 独立。
- 合作协议提供草稿编辑、新版本发布、阅读 / 同意记录。草稿不阻断业务；已发布正文不可修改，服务端对所有伙伴业务检查当前已发布版本同意状态；前端在签署前不挂载业务页面。协议前允许的 auth/me 只返回身份，不返回余额。发布新版本后重新确认，首次阅读和签署记录留存账户、版本、摘要、会话、IP、客户端及时间，同意重试不重复记账。合作申请、绑定和协议管理仅 SUPER_ADMIN。
