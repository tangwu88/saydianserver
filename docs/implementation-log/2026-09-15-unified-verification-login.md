# 2026-09-15 商城统一验证码登录

## 目标与范围

- 去掉商城 H5 登录页中的注册入口和密码登录表单，统一为手机号或邮箱验证码登录，默认展示手机号。
- 国内手机号继续使用后台已经支持的 `sms` 集成与阿里云短信直连；邮箱验证码使用独立的 `email_otp` Webhook 集成，未配置或未完成投递验收时保持关闭。
- 微信 H5 首次授权必须完成手机号验证码绑定；已绑定且手机号已验证的微信身份后续授权直接进入系统。
- 保留旧注册、密码和旧绑定接口供 App 与历史客户端兼容，本轮只移除商城 H5 的相关入口，不删除数据库字段或兼容 API。

## 实现

- 新增商城兼容接口 `POST /auth/code/request` 与 `POST /auth/code/login`：国内手机号复用现有短信记录和阿里云适配器，邮箱及国际手机号使用一次性 challenge；验证码成功后登录已有 ACTIVE 会员，账号不存在时建立无密码会员。
- 验证码 challenge 与账号标识、通道和用途绑定，只能消费一次；已有未验证账号完成验证时撤销旧会话，停用账号不能通过验证码恢复。
- 国内商城会话、受保护商城资源和公众号支付身份允许“已验证手机号或已验证邮箱”，但历史 opaque 会话桥接仍保留原有手机号来源证明边界。
- 国内与国际商城登录页都默认手机号，可切换邮箱；页面不再显示注册会员、密码、忘记密码。国际手机号继续使用国家区号选择与 E.164 标准化。
- 微信首次授权仍返回绑定票据并只允许手机号验证；正式短信验证码本身即为手机号所有权凭证，不再额外索要旧密码。已有已验证手机号的微信身份保持后续直接登录。
- 管理后台新增“邮箱验证码”配置项；邮件发送地址保存在公开连接配置，访问令牌进入现有加密密钥存储，只有 `deliveryVerified=true` 时才向客户页面开放邮箱登录。
- 更新接口目录、客户端路由白名单与单元/组件测试，覆盖默认手机号、邮箱验证码、自动建号、单次消费、国内阿里云路由、微信首次绑定及后续会话边界。

## 验证边界

- 未读取、修改或输出生产 AccessKey、邮件令牌等真实密钥。
- 未发送会产生费用的真实短信或邮件；供应商真实投递与生产微信授权需要上线后用测试账号人工验收。
- 无数据库结构变更或数据迁移。
