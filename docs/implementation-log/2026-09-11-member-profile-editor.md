# 会员资料统一编辑与验证管理

## 目标与边界

- 用户要求国际版会员后台可编辑会员信息，并将手机、邮箱验证操作集中到编辑窗口。
- 本轮允许超级管理员编辑昵称、国际手机号、邮箱和账号启停状态，并在同一表单维护两种联系方式的验证状态。
- 会员编号、密码、健康数据、微信身份、订单和资产不在此窗口修改；注销中或已注销会员不允许绕过注销流程编辑。
- 不新增 Prisma 字段或 migration。现有独立验证接口继续保留兼容，但列表不再放置分散的确认/撤销按钮。
- 修改前 `Start-Change.ps1 -Resume` 因当前为已审阅功能分支而按设计停止，未切换或覆盖工作区；随后手工 fetch 并确认本地、远端 `codex/global-api-foundation` 均为 `9144c69c4ba048825a364bd18ae6465f2c0c5d7b`，ahead/behind 为 `0 0`。
- 原有京东 ERP 抽样记录和两个脚本保持未跟踪，不修改、不暂存。

## 实现

- 会员列表继续只显示脱敏手机号、邮箱和“已验证 / 未验证 / 未填写”标签，每行由超级管理员通过统一“编辑”入口操作。
- 新增受审计的会员编辑资料读取接口，仅向国际版 `SUPER_ADMIN` 返回未脱敏联系方式；列表和其他后台角色不会获得原始联系方式。
- 新增原子资料更新接口，同时保存昵称、联系方式、账号状态和两类验证状态。手机号统一规范为带国家区号的 E.164，邮箱统一小写规范化，至少保留一种联系方式。
- 联系方式输入发生变化时，前端自动关闭对应验证开关；管理员确实完成人工核验后可以再次开启。服务端仍独立校验缺失联系方式不能标记已验证。
- 使用会员 `updatedAt` 做并发保护；重复手机号/邮箱返回 409，不覆盖其他管理员或会员刚发生的修改。
- 联系方式、验证状态或账号状态变化时，同事务撤销会员现有会话，要求重新登录；仅改昵称不额外注销会话。
- 读取及更新均写入专门审计，记录操作人、请求编号、字段是否变化和验证前后状态，不保存完整手机号、邮箱或昵称。

## 上线验收标准

- 超级管理员能从会员行打开编辑窗口，读取并修改昵称、联系方式、验证状态和正常/停用状态；列表不再出现分散的人工确认链接。
- 非超级管理员看不到编辑入口，直接调用资料读取或更新接口也被拒绝；国内服务同样拒绝。
- 联系方式变化会自动关闭验证开关；保存时的重复身份、非法格式、过期版本、注销状态均不能写入。
- 发布后公网 `/global/health` revision 等于本轮提交，国内 `/health/ready` revision 不变；线上验收只打开编辑窗口并取消，不修改生产会员资料。
