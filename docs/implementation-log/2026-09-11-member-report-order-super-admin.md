# 会员资料、后台健康报告与待付款订单人工处理

## 目标与边界

- 国际版总后台会员编辑窗口补齐 App 已保存的头像、姓名/昵称、性别、出生日期、身高和体重，并继续统一维护手机号、邮箱、验证状态和账号状态。
- 国际版 `SUPER_ADMIN` 从总后台生成 AI 健康报告时，不再以会员 App 端健康分析同意为前置；`HEALTH_AUDITOR` 和会员 App 自助生成流程继续执行原同意校验。
- 国际版 `SUPER_ADMIN` 可在新系统待付款订单详情中调整应付金额，或在已核实线下到账后登记为已支付；处理备注必填。
- 不允许任意改写其他订单状态，不处理迁入未接管订单，不绕过支付中检查，不把线下收款伪装为微信或支付宝回执，不自动发起线下退款。
- 修改前已 fetch 并确认 `codex/global-api-foundation` 与远端基线均为 `48a32f956ad61cc586c6ba9f9e73539f2976f336`，ahead/behind 为 `0 0`。提交前再次 fetch 时远端新增微信 H5 支付对账修复 `6872f39b1641e5e643024d907a795e795b8329c7`，已先保存本轮已跟踪修改、快进并无冲突恢复；支付适配器交叉修改随后重新测试。已有京东 ERP 抽样日志和两个脚本继续保持未跟踪，不修改、不暂存。

## 实现

### 会员资料

- 复用 `User` 现有字段，不新增重复的姓名或健康资料字段。编辑窗口增加头像预览和地址、姓名/昵称、性别、出生日期、身高、体重。
- 服务端校验头像 HTTP(S) 地址、真实日历日期、非未来生日、身高 50–250 cm、体重 10–500 kg；未提交的新字段保持原值，兼容旧管理端缓存页面。
- 联系方式、验证状态或账号状态变化才撤销会员会话；只改基本资料不会要求会员重新登录。
- 资料读取和更新审计只记录变更字段名，不保存头像、生日、身高、体重或完整联系方式值。

### 超级管理员健康报告

- 可用性接口返回 `memberConsentBypass`，只有实时角色包含 `SUPER_ADMIN` 才跳过会员同意阻断；健康审核员仍会收到 `consent_required`。
- `HealthReport.adminConsentBypass` 将本次后台授权持久化，避免 API 放行后 Worker 再次因会员同意缺失而失败。Worker 在发送去标识化统计前、进入生成态后和写入结果前复核该授权快照，并始终要求会员账号仍为正常状态。
- 每次申请和读取继续写审计；申请审计明确记录 `memberConsentBypassed=true`。AI 安全提示、报告次数、有效数据天数、供应商配置和 Worker 暂停条件均未绕过。

### 订单调价和线下收款

- 新增 `POST /api/saydian-app/admin/v1/commerce-orders/:id/manual-payment`，仅 `SUPER_ADMIN` 可用。
- 请求包含操作类型、整数分应付金额、2–500 字备注、订单版本和幂等键。服务端使用串行事务和行锁，校验 `NEW_SYSTEM`、`PENDING_PAYMENT`、未支付及无 `CREATED/PENDING` 渠道支付记录。
- 调价重新计算商品行优惠、积分和现金分摊，保证订单金额与售后退款快照守恒；金额不能超过原商品金额减积分再加运费，也不能低于合法现金边界。
- 线下到账创建独立 `OFFLINE_MANUAL` 成功收款记录并推进订单为已支付，触发既有佣金和 ERP 出站规则；支付适配器明确禁止把该渠道发送给微信、支付宝或在线退款接口。
- 备注追加保存到订单时间线，并写专门审计。相同幂等键和参数只执行一次；异参、过期版本、已支付、支付中和旧归属订单均拒绝。
- 订单抽屉展示金额明细和中文收款方式；超级管理员仅在符合条件时看到“调价 / 线下收款”入口。

## 线上验收标准

- 迁移正常应用，API、Worker 和管理端 revision 一致，国际 `/global/health` 返回本轮提交；国内服务 revision 不变。
- 超级管理员会员编辑框能显示并保存基本资料；列表仍只显示脱敏联系方式，非超级管理员没有读取或编辑原始资料的入口。
- 无会员分析同意的正常会员，在有足够有效数据、报告次数和 AI 配置时，超级管理员能提交报告且 Worker 可生成；健康审核员仍被阻断。
- 待付款新订单详情能打开人工处理窗口；未填写备注、支付中、旧版本或非待付款均无法保存。线上验收不实际修改生产订单金额或支付状态。
