# 支付宝付款回跳与状态自动确认修复

## 范围与成功标准

- 支付宝手机网页付款完成后先回到本站无片段 HTTPS 地址，再由本站 303 跳转到对应订单详情页。
- 订单详情重新显示时，对已有待确认支付单自动查单；只有支付宝签名响应与原支付应用、支付单号、金额和渠道交易号全部匹配才更新为已支付。
- 支付成功后沿用既有流程清理结算暂存并进入订单列表；不根据页面回跳或用户提示直接修改支付状态。

## 修复

- 支付宝 `return_url` 改为本站 API 落地地址，避免第三方返回参数与 `#` 单页路由冲突；落地地址只做同源固定跳转，不把回跳当作付款凭证。
- 订单详情 `onShow` 加入一次静默自动查单，覆盖从支付宝返回和稍后重新打开订单两种场景。
- 支付宝交易查询响应已经过支付宝公钥验签，且发起查单前已核对当前 AppId 与原支付单绑定；落库时显式传递该已验证 AppId，不再错误要求查询响应包含官方未返回的 `app_id` 字段。
- `total_amount` 同时接受支付宝 JSON 响应中的安全十进制字符串或数字表达，仍按分精确绑定并拒绝无效、非正数或超范围金额。

## 安全边界

- 异步通知仍必须携带并匹配 `app_id`，本次没有放宽通知验签或身份绑定。
- 回跳地址、按钮文案和浏览器页面均不作为支付成功证据；只有服务端已验签通知或已验签主动查单可以更新支付单、订单及后续 ERP 任务。
