# 2026-10-02 GHCR 离线镜像预加载超时

## 现象与根因

- main `d9040d8deaa3ac248d2d8b3d0694f645bdf75e95` 的 CI、全量验证与三镜像构建均成功；生产预加载因 20 分钟上限超时，部署切换未执行。
- Actions 日志显示每个 8 MiB 分片收到接收回执约需 5.5–6 分钟。每次临时 GHCR 登录完成后，离线接收器立即返回“等待剩余分片”。
- 根因是受限接收器对每个离线分片都执行 GHCR 登录；离线分片验证只使用服务器已有 API 镜像和本地文件，不需要仓库认证。

## 修复

- 将 GHCR 登录条件移入独立脚本：完整离线分片包（分片名、分片内容、传输清单和发布清单齐全）跳过登录；常规部署仍照常登录。
- 离线发送脚本将该条件脚本随受限接收包传送。
- 增加部署工具测试，覆盖离线包跳过登录、普通部署保持登录。
- 没有改变数据迁移、运行服务或回退逻辑；失败的首次传输仅到达分片接收阶段，两个线上健康地址仍返回旧 revision。
