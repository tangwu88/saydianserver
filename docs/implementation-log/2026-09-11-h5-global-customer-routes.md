# 国际 H5 顾客购物路由开放

## 范围

- 用户明确要求开放国际版购物车、下单与支付。按主任务分工只处理前端页面/API 白名单及对应测试，不改变后端身份门禁、国家/货币范围、供应商配置、支付实现或生产开关。
- 在当前共享工作区修改上继续，已重读 AGENTS 和本轮实施日志并检查 Git 状态；遵照主任务本轮安排不重复 fetch、不提交、不部署、不运行根构建。既有国内和 ERP 未跟踪文件保持不变。

## 修改

- `apps/shop/src/realm-config.ts` 开放顾客购物车、结算、订单、订单详情、售后、地址、收藏、优惠券和积分页面。保留已有首页 alias、刷新直达校验；`global-navigation.ts` 与 `realm.ts` 无需额外开关或存储改动。
- API 按 HTTP 方法精确开放购物车、地址、报价/创建、订单操作、物流/售后、收藏/券/积分/评价、markets 及 `POST /payments/create`、`GET /payments/:id`；后两者已对照真实控制器。未发现 `/storefront/help` 控制器，未虚构此入口。
- 继续阻断员工/企微、小程序、旧短信登录、推广绑定、员工赠券与第三方支付回调调用；拒绝跨站、路径穿越、片段/反斜杠等不在白名单内的调用。国际 API base、身份/草稿/锁 namespace 不变。白名单是调用范围，不授予临时验证码账号交易权限。
- `apps/shop/tests/global-h5.test.mjs` 改为正向顾客流程和负向员工/mini/callback 测试；涵盖路径对应方法、全导航入口及刷新直达、国际 token/base 隔离、临时账号服务端 403 原样拒绝，不产生假成功或国内请求。

## 验证

- `node --test tests/global-h5.test.mjs`（工作目录 apps/shop）：37/37 通过。初次失败来自既有测试仍预期拒绝普通下单，改为继续拒绝企微路由后通过。
- 主任务追加的个人中心、Header、临时身份本地拦截和 Vite tab 保留均补行为测试：编译真实 Vue 模板并点击八个购物菜单及购物车入口；检查临时账号“待验证/更换登录”提示、已验证账号不误提示、无员工入口；执行 Vite transform 确认首页/分类/购物车/我的四 tab 及独立 hash base 保留。临时账号本地 403 保留 session、没有购物出站且允许账号读取，普通账号仍按服务端拒绝结果处理。最终 global-h5 40/40 通过。
- 经主任务授权更新 `tools/h5-frontend.test.mjs` 的旧全禁购物断言，改为顾客入口开放而员工入口仍禁止；`node --test tools/h5-frontend.test.mjs` 18/18 通过。未修改 API 或页面源码。
- 本子任务仅完成客户端路由能力；商品购买按钮、个人中心入口、国际地址 UI 由主任务负责。真实 CN/CNY 账号门禁与支付渠道联调由服务端/集成任务验证；本记录不能代表生产购物或真实支付已成功。
