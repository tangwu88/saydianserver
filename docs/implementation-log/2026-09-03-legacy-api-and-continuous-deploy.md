# 2026-09-03 旧接口对照、调用说明与自动部署

## 范围和验收目标

- 对照最新 Flutter 契约、交付小程序及现有商城内部接口，修复可确认的兼容缺陷，分别标明源码覆盖和线上可用性。
- 交付逐路由接口列表、参数/返回说明、脱敏调用示例与可重复的契约检查。
- 固化修改前安全更新、修改后显式提交和 CI 成功后的版本化自动部署；保留维护状态、备份和回滚。
- 不迁移旧数据，不开放生产写入，不修改旧后台、商城支付配置或域名。

## 已确认的源码问题（修改前）

1. V1 支付缺少 multipart 解析，最新 App 的表单 body 不能可靠进入支付适配器。
2. 关爱共享仍把小程序的 `bloodPressure`、`heartReat` 等直接交给 V2 校验，保存失败；返回字段也与旧版不一致。
3. 缺少通知 statistics 路由，旧详情 GET 未按旧契约标记已读，App 提醒数不能闭环。
4. 日健康映射使用服务器时区、按小时覆盖多条记录、缺失值可能转成 0。
5. V1 同步生成随机记录 ID/当前时间后再做幂等校验，重试可能冲突；日批次展开后可能超过 200 条。
6. 小程序使用的部分健康历史列表、单条记录路径未实现。
7. 阈值读取把 null 转成 0，可能产生错误的低值提醒。
8. 现有发布脚本不能保证所有阶段失败后回退，也没有推送 main 后的自动发布连接。
