# 2026-10-01 Say Ring 头像服务器本地存储

## 范围与基线

- 用户本轮明确限定为 Say Ring。国内版、国际版 App 共用后台，但它们原有上传入口不改；本轮不接管其他图片、附件或安装包。
- 国际服务工作树基线 `660cf1b70ad26eb1553751c0475084e12ae037cf`；修改前已核对工作区干净、远端分支同步并执行 fetch。国内主线工作树保持原样。
- 安卓端曾出现“照片可预览，但保存后头像不更新”；原共享头像上传路径依赖当前未配置的对象存储并返回 503。该症状属于现场证据，不把代码修复等同于真实上传成功。

## 实现

- Say Ring Flutter 客户端改用专用国际 API `POST /api/saydian-app/v2/files/say-ring-avatar`；返回原有文件 URL，资料保存接口不变。
- 后端只在国际 realm 提供专用入口。写入开关默认关闭；关闭时保持旧上传行为。开启后验证实际 JPEG/PNG/WebP 内容和 10 MiB 上限，使用 Sharp 去元数据、按比例缩放至最长边 1024，再写入服务器生成的随机文件名。
- 文件先以私有临时名写入并同步，原子发布到最终路径且同步目录后才登记 `FileObject`；数据库失败清理该文件。读取按严格版本键定位本地文件并校验长度和 SHA-256；旧键继续从原对象存储读取。不迁移、不删除旧头像。
- 国际 API 容器只读根文件系统不变，仅挂载专用持久卷。另设只读源卷的每日备份容器与独立备份卷，归档校验和七天保留。无本地目录时明确失败，不回退到临时目录或 MinIO。

- Say Ring 定向 Flutter API 测试：27/27 通过，确认请求专用端点及保持原 URL 响应契约。

- `pnpm api:docs` 与 `pnpm api:docs:check`：355 条路由通过；`node deploy/global/check.mjs`：205 项结构校验通过。本机没有 Docker，原生 Compose 解析及真实卷/备份仍未验收。
- `TMPDIR=/private/tmp pnpm tools:test`：11 项工具、61 项 H5 流程及 38 项 H5 契约测试通过；`pnpm typecheck`：8 个工作区项目通过；`pnpm build`：全部项目通过，只有既有 Sass/大块提示。

## 分阶段上线门禁

1. 发布双读取代码、专用卷和备份定义，但保持生产开关关闭；核对 CI、线上 revision、磁盘容量、数据库备份和原国际/国内路由。
2. 在服务器显式启动新备份容器，检查首份归档与 SHA-256，恢复到隔离目录并比对文件，检查 API 卷写权限。自动发布当前不负责启动新增 sidecar。
3. 完成上一步才单独开启 Say Ring 本地头像写入；用专用测试账号真实上传，保存资料，核对首页与个人资料头像，并重启容器后复读；旧对象存储头像和原国际上传入口仍要复核。
4. 关闭开关可停止新写入，但双读取与两个卷必须保留。两卷在同一主机，不算异地容灾；如任一门禁未完成，则线上故障仍未宣告修复。
