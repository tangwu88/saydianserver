## 定位和实现

- 在中国站现有登录会话中只读打开申请页，点击空表提交，控制台真实复现 `TypeError: e.preventDefault is not a function`。Uni form 发出自定义提交对象，Vue 的 `.prevent` 导致请求前中断。改为 `@submit`；保留服务器已验证会员、幂等、防重复申请和总管理员审核流程。正式页面未填写资料或创建申请。
- 修复 Uni form 默认 inline 和编译后原标签选择器无法覆盖组件的问题：表单显式 block，字段/输入使用独立 class；错误靠近提交按钮显示。收到成功申请回执立即显示 PENDING，再刷新进度；刷新失败不回到可重复申请的空表。
- 有效伙伴来源的短信/邮箱登录和微信授权注册返回个人中心；微信发起授权时也保存相同返回页。兼容旧二维码，忽略遗留购物跳转；普通购物登录保留自己的返回路径。首个有效来源、服务告知、注册事务内归属、已有会员不改归属等逻辑不变。
- 商城个人中心头像昵称卡增加资料入口，新建个人资料页：头像、昵称、性别、生日、身高 cm、体重 kg。性别三项直接点击，手机不需要滚动选择。读取未知身高/体重保持空，不写零；字段验证与 App 共用 MembersService。
- 新商城 GET/PUT `/storefront/member-profile` 与 POST `/storefront/member-profile/avatar` 接入同一会员表和现有 App 头像存储，UserAuthGuard 取当前身份，响应不缓存。仅提交允许资料字段，不修改联系方式验证、角色、伙伴归属或会话。头像验证实际字节、格式、10MB 上限、限频，保存时核对本人 ACTIVE avatar 文件，拒绝跨会员文件和外部 URL。
- 前端沿用现有会话刷新与版本围栏；上传和保存结果在账号/页面变化后丢弃，本地缓存只更新昵称头像，保留验证信息。路由/接口白名单及三条接口文档已更新；不改 App 仓库、数据库 schema 或生产配置。
