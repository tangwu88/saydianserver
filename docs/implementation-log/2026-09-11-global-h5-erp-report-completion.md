# 国际版 H5、ERP 订单与后台健康报告闭环

## 目标与基线

- 工作仓库：`F:\xcodeplace\saydian-server-global`，分支 `codex/global-api-foundation`。
- 修改前及发布前 fetch 基线：本地与 `origin/codex/global-api-foundation` 均为 `ec97bc28c5048e61451d33f01cedcc2abbd7cac9`，ahead/behind 为 `0/0`。
- 目标：完善 H5 的支付后返回、最近订单、商品回跳、优惠码、折叠式结算和商品分享；修复聚水潭已付款订单出站；让超级管理员在后台直接生成信息更完整的 AI 健康报告。
- 边界：不修改国内版 `main`，不导入或伪造真实历史数据，不在测试中产生真实支付、退款、提现或 AI 报告；保留已有未跟踪的京东抽样导入日志和脚本，不暂存。

## 实现记录

### H5 购物流程与界面

- 支付由服务端确认成功后清理本次结算状态并跳转订单列表，刷新或轮询不会重复下单。
- 个人中心读取并显示最近 3 条订单；全部、待付款、待收货、售后入口继续使用服务端筛选的订单页。
- 订单列表和订单详情中的商品图片可回到对应商品详情；商品详情移除“帮助与售后”，该入口只保留在个人中心。
- 结算页将优惠券、积分和订单备注折叠为一个可选区域，默认收起；发票输入已移除。优惠码先由服务端领取为会员优惠券，再以优惠券领取记录参与统一报价和下单，浏览器不能自行改价。
- 后台优惠券沿用新国际库中唯一的外部编号字段保存 4–32 位大写优惠码，并通过管理端显示和校验；未设置优惠码的普通券不受影响。
- 商品详情使用 Uni Icons 图标库强化首页、分享、购物车、收藏和购买动作；分享生成带商品标题、价格、二维码及推广参数的海报。
- 商品加载后调用 `uni.setNavigationBarTitle`，TITLE 使用实际商品标题；R7 青春版实测标题为“R7青春版”。

### 聚水潭订单出站

- 将默认网关改为聚水潭正式地址 `https://open.erp321.com/api/open/query.aspx`，按官方 `method/partnerid/token/ts/sign` 顺序签名并以 JSON POST 调用 `jushuitan.orders.upload`。
- 已付款订单报文补齐官方必填的 `receiver_phone`、`shop_sku_id`、`base_price`、支付方/收款方账号；`pay` 使用单对象而非数组，买家留言和后台备注分别映射。
- 店铺编号必须为正整数；支付成功记录必须唯一且金额与订单应付一致，否则进入需人工对账的死信边界，不把有资金差异的订单推给 ERP。
- 顶层成功但单订单 `issuccess=false` 或没有逐单结果时不标记同步成功；只有逐单成功后才写 ERP 单号并推进待履约状态。
- 日期固定按 Asia/Shanghai（UTC+08:00）格式化，避免 Linux 容器默认 UTC 导致订单时间偏移。
- 总 Worker 仍保持暂停时，仅在 `JUSHUITAN_OUTBOUND_ENABLED=true` 且业务写入未冻结的情况下处理 `JUSHUITAN_*` 任务；不顺带放开通知、结算或其他出站任务。
- 线上聚水潭公开配置只保存店铺编号，接口服务器和方法均为空，发布后会使用上述官方默认值；加密凭据未读取、未记录。

### AI 健康报告

- `SUPER_ADMIN` 在国际版总后台生成报告时可跳过会员前端同意和会员报告次数，两个绕过决定均写入审计；健康审核员和会员自助流程仍执行原授权、次数与付费规则。
- 报告证据增加去标识化的年龄、性别、身高、体重、BMI、语言、时区、活动目标、设备概况、近 30 天预警汇总，以及各指标的最新值、最小值、最大值、均值、中位数和逐日均值。
- 姓名、手机号、邮箱、账号编号、设备硬件标识、健康记录编号和任意未列入白名单的原始字段不发送给 AI。
- 提示词要求先检查数据量、单位、覆盖期和异常值，只输出审慎的健康趋势及低风险、可执行的日常建议；禁止诊断、处方、药物剂量、准确性承诺和虚构指标。
- 总 Worker 暂停时仅在 `HEALTH_REPORT_WORKER_ENABLED=true` 且业务写入未冻结时处理健康报告事件；其他 Outbox 事件继续暂停。

## 调试问题与修正

- H5 首轮专项测试有 2 项旧断言与新导航行为不一致，按新支付成功返回和商品回跳契约更新后通过。
- 本地契约包构建产物一度落后，先构建 `@saydian/app-contracts` 后恢复真实导出，不通过复制函数规避。
- 健康报告并发测试受调用时序影响，改为先建立管理员报告再验证复用，保留原事务锁和幂等语义。
- TypeScript 对测试替身元组推断过窄，改为显式测试类型，不修改生产类型。
- Vite 优化 `qrcode` 时无法解析其传递依赖 `dijkstrajs`，将该运行依赖直接锁定并以 `--force` 重启本地 H5；页面随后真实挂载。
- 新增接口最初缺少接口中心说明，补充脱敏示例并重新生成目录后通过差异检查。
- 聚水潭官方文档复核发现旧报文把 `pay` 发送为数组且缺少多项必填字段，发布前改为官方对象结构并增加逐单失败测试。
