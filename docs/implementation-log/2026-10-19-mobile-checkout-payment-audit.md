# 手机商城登录、下单与支付流程复核

## 请求与基线

- 用户要求全面检查手机购物，特别是微信内登录、下单、微信和支付宝支付，并要求继续更新。Start-Change.ps1 在干净 main 上将 0049c72 安全快进至 fb63cc1371247cea22196d7b8cb78dbd50c617e9；独立分支 codex/mobile-checkout-payment-audit-20261019。
- 线上双商城公开能力显示：微信公众号登录与短信已启用；微信内 JSAPI、浏览器支付宝 WAP/PAGE 已启用；没有将未公开的微信 H5/Native 渠道当成已接通。本轮不修改商户凭证、后台权限、法律版本、价格、生产会员或真实资金。

## 发现与修复

- 结算页原来固定取第一个可用支付，增加明确的支付方式选择；支付宝 PAGE/WAP 按屏幕环境选择，不重复显示同一提供方。
- 微信 JSAPI 立即读取 WeixinJSBridge 会遇到组件未就绪；按照微信官方调起示例等待 WeixinJSBridgeReady，设置就绪超时并清理监听，只传六个签名字段。就绪后再次校验页面/账户上下文，取消或失败不当成支付成功，仍以服务端查单为准。参考 https://pay.wechatpay.cn/doc/v2/merchant/4011935213 。
- 保留后端“微信内 JSAPI、普通浏览器支付宝”的渠道隔离。为另一支付环境提供订单链接接续：先以原报价/幂等键保存一笔订单，不在错误环境调用供应商；复制的是当前站点订单链接，无令牌、验证码或地址。外部浏览器重新登录原下单手机号后，继续同一订单；付款意图保留在登录返回路径。
- 订单轮询原来会把支付方式重置为首选，现保留用户选择。已有 CREATED/PENDING 付款时仅提供原渠道和对应环境接续，不假装可以自由切换；原支付未确认关闭前不绕过服务端单一有效付款限制，超级管理员关单权限保持。
- 微信登录入口前移，首次手机号验证与同意协议仍由用户本人完成。短信登录后若公众号身份不足，订单付款错误提供重新微信授权入口，返回原订单，不自动合并或替换账户。
- 原报价重核、未知创建结果恢复、账号切换隔离、跨标签锁、支付幂等及支付宝原签名表单保持。
