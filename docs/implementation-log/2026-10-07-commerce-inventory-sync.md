# 后台商品列表聚水潭库存同步

## 原因、基线与范围

- 用户要求后台商品列表增加聚水潭库存同步按钮，查询库存后更新本站商品，并提交 Git 发布线上。
- 已阅读 AGENTS、handoff 和最近记录。原工作区有未跟踪文档，原发布工作区另有其他任务日志，全部保留；在独立 worktree 的 main 开发。
- 成功 fetch 并安全快进，Start-Change.ps1 建立检查点；本地与远端基线均为 48d493275205a4e755805080494dd5b6fe42c51d。
- 只修改后台商品管理与支撑接口，不修改原生 App、schema、旧库、集成配置或生产业务开关。

## 实现

- 商品列表顶部增加“聚水潭库存同步”，运营/超级管理员可用，同步期间防重复点击，结束显示商品数、SKU数、变更数并刷新列表。
- 新增 POST commerce-products/inventory-sync，继承鉴权、维护状态和管理员审计；查询未归档 ERP 商品的启用且映射 ERP 编码的 SKU，本地商品和停用规格不参与。
- 复用现有聚水潭签名、配置、20秒单次请求超时及库存口径（优先 avl_qty，兼容 qty，负数限制为零）。分100 SKU查询并读取后续页面，只更新库存，不重新导入商品或覆盖价格、图片、上架状态。
- 完整验证返回后在事务写入。任一 SKU 缺失、数量无效或分页不完整则不写入；使用 SKU 原 stock/updatedAt 和当前 ERP 归属校验，防止覆盖查询期间订单扣减或人工修改，冲突整次回滚。单次最多5000 SKU，库存请求总预算40秒、事务超时10秒，适配现有网关超时；没有符合条件的 SKU 返回零统计，不调用供应商。
- 新增接口说明、字段契约、库存同步测试；复用后台实际 SFC 测试覆盖请求、摘要、刷新、重复点击、错误恢复与只读限制。
