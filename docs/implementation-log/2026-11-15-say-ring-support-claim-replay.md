# Say Ring：访客会话关联收到重复请求

2026-11-15（北京时间）。服务端基线 `e926c29`，客户端使用 1308 已验证代码。此次仅调整客服会话关联的服务端回执，未更改接口、表结构、安卓制品、账号照片或现网配置。

## 复现与修复

- 安卓模拟器继续用真实客户端界面和本地隔离 PostgreSQL 测试图片重试、断线补收和访客会话关联。发现首次关联已完成，但 App 若没收到确认，第二次提交会因访客不再拥有该会话得到 404。基线上的真实 HTTP 对照为首次 201、原会员重试 404、另一会员 404。
- 在客服会话原有事务锁内校验访客归属或当前已归属的同一会员。首次关联仍需有效访客凭据及已登录的有效会员，且仅转移指定会话；同一会员对已经归属自己的会话重试返回现有结果，无再次改写。其他会员持同一个旧访客凭据仍返回 404，游客旧凭据也不能再访问已关联的附件。
- 专用真实数据库回归补上首次关联、同一账号重试且结果不变、另一账号重试被拒绝。客户端仍需本人主动确认关联，没有自动合并。

## 验证

- 安卓侧在单独的 Android 16 / ARM64 模拟器中用系统相册选取合成照片，上传已提交后故意丢掉回执。重试后同一消息 ID 且数据库仅一份 JPEG，原始 EXIF 等元数据未公开；有权限的坐席能读回相同附件。
- 实际 SSE 连接切断时，坐席提交两条回复。在 App 未重新加载页面的情况下，恢复网络后从上次消息编号补取，每条只显示一次。
- 同样在关联操作已入库后丢弃首次确认。重试恢复照片及原会话；主动取消不改变访客归属；关联完成后旧访客和另一会员读图被拒，换账号时已打开的照片也立即隐藏。测试成功后本地服务隔离关闭。
- 第一轮模拟断言错误地要求 Flutter 的图片异常继续携带 HTTP 状态；产品故意给用户通用的照片不可用提示。复测分别断言客户端拒绝显示以及接口的 401/404，未为通过测试改变图片处理。

- `pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm api:docs:check`（601 条路由）、`pnpm tools:test`、Prisma schema 校验和 `git diff --check` 通过。常规 API 1,584 项通过；启用隔离实库的在线客服、同步诊断和应答三组定向测试合计 35 项通过。
