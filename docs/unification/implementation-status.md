## 客户端契约基线

`apps/api/src/legacy/fixtures/flutter-fa79aa3-consumers.json` 冻结了两个 Dart 文件的调用点。74 个不同路径源码字符串归一为 **72 个路径、76 组 HTTP 方法+路径**。

运行 `pnpm contracts:client:check` 检查路由缺失；它不会检查所有响应字段，不会证明旧会话或真机通过。新增/删除控制器会由 `pnpm api:docs:check` 和工具测试阻止漏文档。

改 `SAYDIAN_API_BASE_URL` 需要重打包，已经安装的 App 仍需旧域名接到新服务。部分相对媒体地址仍依赖旧域名。保持两域名和旧媒体 URL、正确迁移 ID/会话是零业务代码过渡前提；客户端未上传的测量时间、设备信息、多样本 ID 不能由服务端补造。

## 本地验收边界

- 最终根级类型检查和构建通过；230 项自动测试、7 项工具测试、4 项显式 PostgreSQL 事务测试通过。旧 Flutter 的 76 组路径/方法没有缺失；独立 HTTP 工具连续三次各 95 断言通过，包含本轮 8 条新增路由，但不是全部 76 组的字段/业务端到端验收。
- 内部浏览器完成登录、折叠菜单、LOCAL 商品保存回读、提现入口和接口示例检查。临时账号、商品和 HTTP 测试实体已按本轮 ID 清理。启动本地开发时如果共享 contracts 更新后 Vite 留存旧依赖缓存，构建 contracts 后用 `vite --force` 重启。
- 新增三项 migration 已应用到本地库（共 7 项）。改造前备份实际恢复到独立临时库，77 张表且约束有效；该本地备份无用户/健康/交易数据，不证明真实数据迁移正确或 30 分钟可达。临时库已清理，备份保留。
- 本轮只应用到回环 PostgreSQL 测试库，不代表生产数据迁移。
- 自动测试中的支付/退款/提现供应商是隔离的合成响应；没有产生真实付款、退款、短信或推送。
- “全部旧业务一次性接管”是上线目标，**不是当前完成状态**。迁移 gate 不通过时旧交易保持 LEGACY_SYSTEM 所有权锁；这不是允许两个引擎同时处理，也不允许跳过冲突强切。
- 正式上线仍需用户确认窗口，并执行 [迁移切换手册](migration-runbook.md) 的所有资金、身份、附件和恢复门槛。
