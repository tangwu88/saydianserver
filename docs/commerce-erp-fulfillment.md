# 商城订单与 ERP 履约同步

总后台、伙伴平台和会员中心共享履约状态显示。ERP `Cancelled` 将本系统已付款、待发货、已发货订单转为 `CANCELLED`；ERP `Sent` 且取得本单有效运单才转为 `SHIPPED`。仓库处理中和已打印面单不视为实际发货。售后、已退款、已收货、已完成、已关闭、原已取消和未支付状态不由该同步覆盖。

ERP 取消只表示履约取消，不触发现金退款、返还余额、释放库存、恢复兑换卡或再次推单。已付款且由 ERP 取消的订单仍可走现有人工审核售后；礼品兑换仍只允许换货，不新增现金退款入口。后续恢复发货不能仅凭旧 ERP 回执自动重新开启已取消交易，须先核对业务状态。

## 会员接口

基址 `/api/saidian-mall/v1`（兼容 `/global/api/saidian-mall/v1`）：

- `GET /storefront/orders/:id/processing`：只读已有同步快照和任务状态。
- `POST /storefront/orders/:id/processing`：缓存超过一分钟时创建一次异步只读查询任务；不创建新订单、不调用支付。

两者均使用 `UserAuthGuard`，从已认证会员 ID 限定查询后才读取数据和创建任务。返回 `state`（`WAITING_ORDER`、`UNAVAILABLE`、`PENDING`、`READY`、`ERROR`）、`orderStatus`、`erpStatus`、`syncedAt`、包裹和经过限制的发货事件（仅编号、名称、时间）。会员不能取得 ERP 内部备注、操作人、原始供应商凭证或其他会员订单。

会员订单列表读取时，对当前会员结果中最多二十笔过期履约快照排队；每单每分钟与后台、伙伴刷新共用同一幂等键。列表有待执行任务时最多刷新十二次，详情首次进入和点击刷新时同样有界轮询。离开页面、切换账号或启动较新请求后，旧结果不得覆盖当前页面。

## 运单、轨迹及失败边界

Worker 使用 `orders.single.query` 同时核验 ERP 内部订单号、本系统订单号和店铺号，再保存状态及操作日志。实际发货后，`logistic.query` 查询本单发货包裹，识别官方 `orders` 响应和已有适配器 `datas` 响应；最多二十页，每页五十条。多包裹按订单和运单唯一键更新，不产生重复包裹。供应商返回了订单或店铺标识时必须同时匹配，不匹配的数据丢弃。

参考聚水潭官方 [订单查询](https://open.jushuitan.com/document/2125.html) 与 [发货信息查询](https://open.jushuitan.com/document/2159.html)。该发货接口主要返回发货资料，不保证提供快递在途轨迹；本系统只显示供应商实际返回或既有已保存的轨迹，不把 ERP 操作日志、打印面单、时间字段拼成运输事件，也不启用未经配置的新供应商。无轨迹时显示“已获取运单，快递运输轨迹暂未返回”。发货查询暂不可用时保留已核实运单与旧轨迹，不清空。

快照写入使用订单版本、ERP 绑定及更新时间的比较更新；核验失败、订单在查询期间变化、事务写入失败均不得覆盖新状态。重复任务只更新快照和包裹，不扣款、扣库存或重复礼品核销。

本次无数据库结构迁移，也不修改 ERP 店铺推送地址、密钥或美国站配置。真实 ERP、线上版本及页面验收以当次实施回执为准，合成轨迹测试不代表快递供应商联调成功。
