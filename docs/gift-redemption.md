# 商城礼品兑换

## 业务与使用

总后台“商城 → 礼品兑换”管理兑换卡、生成批次和兑换记录。总管理员负责生成、首次下载、启用、改绑和作废；商城运营只能查看卡片和兑换记录、进入关联订单。所有写权限由服务端校验。

每张卡兑换一款商品的一件允许规格，商品和运费全免。默认不限有效期，可指定截止时间。ERP商品库存为零或负数时仍可选择兑换，沿用付款扣库存的负库存补货记录，并在同一事务中生成ERP推单任务；LOCAL商品缺货仍不能核销。规格停用、商品下架、过期、作废、未启用不能核销；不在发卡时占库存。

卡号是8位数字：`8 + 两位发卡商品编号 + 五位流水号`。例如商品12第35张为 `81200035`，商品1第1张为 `80100001`。商品编号由系统在首次发卡时分配，范围01–99；同款流水跨批次连续递增，范围00001–99999，作废不回收。编号用完明确拒绝，不截断或复用。校验码是加密随机生成的6位数字。

每张卡另有数据库自动递增的管理编号，如1、2、3，写入`CommerceGiftCard.number`并设唯一约束；列表按编号从大到小排列。CSV、二维码说明、兑换记录和新订单备注均使用此数字。原复杂编号保留作内部兼容追溯，已导出文件、历史订单和审计不重写；卡号与校验码不变。API的`serialNo`仍为字符串，但内容为数字管理编号。

按用户最终确认，未启用卡允许跨商品改绑，卡号保留最初发卡商品编号；实际兑换商品和规格按当前绑定校验，前后变更及原因进入审计。启用后不能改绑。

## 生成、导出与启用

1. 总管理员选择商品、允许规格、批次名称、数量（每批1–100张）和有效期，点击“生成并下载”。
2. 浏览器下载UTF-8 BOM CSV，包含编号、卡号、明文校验码、绑定商品、有效期和兑换链接。
3. 检查文件已保存且可打开，确认后启用；也可在批次或卡片列表稍后启用。
4. 服务端无法重新导出明文；下载中断或文件丢失时先作废原卡再生成。重复请求只返回原批次元数据，不再返回CSV。

只有首次成功生成响应含明文，数据库只存bcrypt成本12的带盐哈希。响应不缓存，审计不保存CSV、校验码或哈希。二维码仅包含兑换入口及卡号，不包含校验码，可单独下载。

## H5兑换与订单

入口：`/global/saidian-mall/#/pages/gift-redemption/index`，兼容既有 `/saidian-mall/` 页面部署。开启后个人中心显示“礼品兑换”。微信内置浏览器和桌面均使用独立短信验证，不要求微信支付或公众号授权。

流程：验卡 → 选规格 → 本次手机短信验证 → 选择或新增地址 → 核对商品、规格、数量、地址和零元金额 → 确认兑换。已有手机号会员登录原账户，新手机号同意当前商城已审已发布的用户协议与隐私政策后注册；协议不可用或已更新时拒绝旧版本同意。

验卡/会话接口按每个允许规格返回`redeemable`和`estimatedDispatchDays`：库存大于零预计2天发货，否则预计7天发货，库存使用本系统最近同步的ERP规格库存。确认页面使用服务端重新报价的时间，并显示“个性定制产品，发货时长稍长，请耐心等待。”发货天数进入确认摘要；2天/7天之间发生变化时提交不核销、不扣库存，要求重新确认；同一时间档内库存变化不使确认失效。缺货兑换不绕过手机验证、卡片和商品有效性、幂等及事务保护。

点击兑换商品标题在当前页打开商品详情弹窗，按需读取对应商城`/storefront/products/:id`，复用原商品详情HTML渲染和图片懒加载。关闭弹窗保留兑换进度，加载失败可重试，手机显示底部面板、桌面显示居中窗口，支持关闭、Escape及键盘焦点返回。

验卡凭证30分钟有效，短信300秒有效，每条最多5次验证；手机号验证证明15分钟有效，绑定卡片、会员及会员会话。订单手机号来自验证记录；收货电话可不同。前端不能自报会员ID、验证时间或来源IP。

兑换接口和礼品管理接口保留可操作的中文业务提示：卡号或校验码不正确、尚未启用、过期、已兑换、验证失效及限频分别提示，HTTP状态不变。只有卡密匹配后才显示卡片状态，不能凭卡号查询有效性；校验码取自兑换卡或首次导出文件，与手机短信验证码不同。未知服务异常继续隐藏内部错误、哈希和凭证，不影响其他商城/App接口的既有语言规则。

冻结的请求保存在当前标签的sessionStorage，刷新及网络失败保留原请求键与参数，先查原结果，避免重开订单。缓存不包含校验码或完整地址。切换会员清除页面私有地址与报价，不能继续使用旧会员的验证证明。

同一事务锁定卡片和SKU，重新检查规格、库存规则、预计发货时间、地址归属及确认摘要，创建商城订单、零元成功结算凭证、扣库存、写兑换记录及ERP任务。唯一约束保证一卡一单；任何失败全回滚。结算渠道为仅服务端可创建的 `GIFT_REDEMPTION`，无外部支付交易号，不叠加券、积分或佣金，不计虚假现金收入。

ERP沿用现有推单、重试、发货、包裹、物流和日志同步；传真实ERP SKU及本系统SKU，礼品明细实收、运费、付款金额均为零，保留商品零售价快照，备注带“礼品兑换”和管理编号。重复执行任务不会重扣库存。LOCAL商品使用既有本地发货流程。

商城及后台订单可按来源筛选，显示“礼品兑换”和编号。礼品订单不能再次付款或现金退款，使用现有换货审核流程；其他售后联系客服，核销卡不自动恢复。

## 记录与接口

记录包含会员UUID、会员数字编号快照、验证手机号、验证与兑换时间、可信代理后的请求IP、商品与地址快照及订单号。过期验证凭证及24小时前的限频键会在后续允许的兑换写请求中分批清理；不改写兑换交易。账户注销沿用原匿名化策略，移除验证会话，并脱敏兑换记录的手机号、IP及地址快照，保留交易标识和金额。

- 后台：`/api/saydian-app/admin/v1/commerce-gift-*`，含批次、卡片、记录、商品选项、二维码、操作和开放设置。
- H5：`/api/saidian-mall/v1/storefront/gift-redemptions`，含capabilities、validate、session、sms/request、sms/verify、preview、submit、result。
- 精确字段、权限及示例结构以生成的[接口目录](api-reference.md)及 `tools/gift-field-contracts.mjs` 为准。

## 验证、部署与本地预览

正常串行门禁之外执行 `pnpm test:gifts:upgrade` 和 `pnpm test:gifts:database`；DATABASE_URL必须是回环PostgreSQL控制库。工具只创建和删除本次随机临时库，升级演练逐字段比较原表及合成旧订单，事务测试覆盖并发、库存、回滚、卡密、短信与权限。CI包含这两个阶段。

礼品事务测试强制数据库时区Asia/Shanghai，以检验UTC存储的凭证有效期、限频窗口、交易时间和ERP任务调度；不能用数据库默认UTC掩盖时区差异。验证记录清理只移除到期凭证，不移除卡片、已核销记录或订单。

兼容迁移依次增加支付渠道枚举、新表及默认字段、唯一约束、外键和金额检查，以及卡片自增管理编号。历史订单的礼品字段为空/零；不转换优惠券、原支付或伙伴资金，不运行生产seed。新增编号只填充新列，不修改原卡密、状态或订单。精确SQL摘要登记于 `deploy/compatible-migrations.json`，生产仍须通过既有备份、迁移及维护状态门禁。

新功能默认关闭，读取私有设置 `commerce_gift_redemption.enabled`。总管理员在本模块完成短信和ERP联调后开放，不自动改变维护、停写或Worker状态。首次真实兑换前可回退原镜像并保留新增结构；出现真实 `GIFT_REDEMPTION` 记录后应使用兼容版本回退或向前修复，不能让旧客户端ORM读取不认识的枚举。

本地隔离预览：先启动本地PostgreSQL到回环55437，再执行 `node tools/gift-local-preview.mjs prepare`，分别执行 `api`、`admin`、`shop`。管理页为 `http://127.0.0.1:3308/admin/commerce-gifts`，H5为 `http://127.0.0.1:5197/global/saidian-mall/#/pages/gift-redemption/index`。私有本地配置在ignored artifacts目录，短信固定123456，商品、协议、账户均为合成验收数据，不启动Worker或调用真实短信、支付、ERP。
