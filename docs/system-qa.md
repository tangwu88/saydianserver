## 本轮修复

1. 裸密码注册不再创建未验证手机号账号；商城登录及受保护购物入口校验手机号验证。已停用/注销账号不得通过短信、微信App或小程序登录被自动恢复。
2. 最后一个启用的超级管理员不可停用或降级；并发角色变更使用事务锁。内容和注销入口的前端权限与已有服务端约束一致。
3. 新增LOCAL订单发货预览及手工分包接口/界面，校验来源、接管权、已付款状态、版本、商品归属和售后占用。相同运单同内容幂等；冲突不额外建包裹。
4. 部分发货保留待发货状态，全部发完才可确认收货。售后处理后按已有包裹恢复状态；归属不明时要求复核。LOCAL售后不再安排ERP任务，仅退款不再显示退货物流流转。
5. H5使用同源Web Locks保护共享会话刷新与结算创建；账号变更主动清掉另一标签已渲染的个人页面，迟到响应不能写回旧身份数据。员工身份仍独立。
6. 健康批次、幂等响应和Outbox同事务提交；同记录编号异参/不同设备明确冲突。同时间戳分页改复合游标，继续接受旧ISO时间。首次未绑定设备上报仍允许，来源哈希保留身份，历史未知值不反推。
7. 预警设置先全量校验再原子保存；内容与通知分页拒绝非法小数/无限值并稳定排序；公开客服接口不读取 `public=false` 的配置。
8. 工作台中文标签、金额单位和统计口径提示；发货表单区分商品规格，H5显示包裹中的商品数量与未知轨迹。

## 可重复执行

在仓库根目录、依赖与共享包已构建且演示API已启动时运行；全部串行，不与其他测试同时修改共享配置。

```powershell
$qaProfile = 'F:/xcodeplace/saidianserver-local-runtime/h5-demo/.env.h5-demo'
$env:RUN_SYSTEM_QA = '1'
# 第一次没有私有账号文件时，通过SYSTEM_QA_TEST_PASSWORD提供独立测试密码；已有文件则无需再传。
node tools/system-qa-scenarios.mjs $qaProfile
node tools/system-qa-http.mjs $qaProfile
node tools/system-qa-db.mjs $qaProfile
Remove-Item Env:RUN_SYSTEM_QA

$env:RUN_H5_APP_HEALTH_ACCEPTANCE = '1'
node tools/h5-app-health-integration.mjs (Get-Location).Path $qaProfile
Remove-Item Env:RUN_H5_APP_HEALTH_ACCEPTANCE

node tools/system-qa-role-matrix.mjs (Get-Location).Path
node --test tools/h5-cross-tab.test.mjs tools/h5-frontend.test.mjs tools/h5-checkout-recovery.test.mjs
```

`system-qa-scenarios`保留自身数据，只补缺不重置订单/库存/积分；`system-qa-http`沿真实API推进自身订单，临时停用测试会员后按原状态校验恢复，尊重60秒短信冷却。不要人工删改标识数据后期待同一套断言仍成立。

健康/关爱综合回归使用每次新的随机标识，结束精确清理自己创建的数据，要求 `passed=true`、`cleanupVerified=true`。原有商城积分/退款/员工联动脚本继续保留，运行方式见 `h5-demo.md`。角色矩阵为纯Guard授权检查，不等于真实HTTP；两种证据分开记录。

保留订单的“paid”场景已通过浏览器登记一个模拟包裹，因此当前实际状态为部分发货；“split-shipment”有初始包裹与并发请求胜出的包裹。场景名称是创建意图，不强行把已推进业务改回初态。

当前仍不能声明整个系统已可无条件上线：

- 真实短信送达、公众号/企微/小程序手机绑定、支付扣退款、渠道主动查单、ERP写入、推送与提现回执，必须取得外部授权并完成真实联调；没有用本地测试替代。
- H5跨标签锁只覆盖同源、同浏览器分区的新版本页面；缺少Web Locks的旧浏览器会明确阻止新登录/刷新/下单，允许浏览和退出。真实微信WebView和多设备仍需验收。
- 新增购物手机号验证不替历史记录自动背书。旧会话/会员的验证来源必须在迁移时核实；Flutter的路由覆盖测试不能代替字段解析和真机升级验收。
- 换货在退回后的再次换出流程仍未形成完整专用闭环；部分发货后已完成售后且无法辨明已发/未发归属，需要人工核验，不能强行自动发货。
- READ_ONLY是业务只读角色，不等于全面脱敏角色；现有成本、发票/地址等细粒度字段权限，以及数据范围限制，仍需按正式岗位需求专项收口。
- 部分后台资源仍有500条上限，经营分析口径、完整大数据分页/导出、生产迁移/恢复演练、真实设备/附件存储和报告产出未因本次局部回归自动通过。

本轮不提交、不部署、不迁移历史真实订单。正式放量前还需安全、数据迁移、资金对账与供应商回执门槛，不能仅改域名即开始营业。
